# Working with AI coding agents

Coding assistants are good at Qt and bad at libraries they have never seen. Fluent Blue ships briefs that describe each component from its own source, so an assistant works from the real API instead of guessing.

## What ships

| File | Purpose |
| --- | --- |
| `AGENTS.md` (repository root) | The rules of the library and an index of every component brief. Tools that read `AGENTS.md` pick it up automatically. |
| `docs/ai/components/<Name>.md` | One brief per component: purpose, import, signature, parameters, signals, public methods, a verified example and usage guidance. For instance, [Button](ai/components/Button.md) or [DataTable](ai/components/DataTable.md). |
| `llms.txt` (repository root) | A machine-readable index in the llms.txt format. |

Every brief ends with the project rules: import from `fluent_blue.compatibility.qt`, style through tokens rather than `setStyleSheet`, keep theme switches fast, verify on both bindings, and never report a result that was not run.

## In Design Studio

Each component section has an **AI Prompt** tab with a **Copy prompt** button. Paste it into any assistant together with your request.

## From the command line

```bash
python -m fluent_blue.agent_prompts Button            # print one brief
python -m fluent_blue.agent_prompts --list            # component names
python -m fluent_blue.agent_prompts --library         # the whole-library brief
python -m fluent_blue.agent_prompts --export .        # regenerate AGENTS.md, llms.txt and docs/ai/
```

## Why the briefs stay correct

The briefs are generated by introspection, not written by hand. The example in each brief is the catalog snippet that the test suite executes on PyQt6 and PySide6 in every theme. `tests/test_agent_prompts.py` checks that every constructor parameter and declared signal appears in the brief, that every parameter has a description, and that the committed files equal a fresh export. CI runs the export and fails if anything differs.
